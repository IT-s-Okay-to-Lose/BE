선택: Conditional UPDATE
사전에 고정한 판정 순서 — 정합성 → deadlock/안정성 → 처리량 → 구현 복잡도 — 를 결과를 본 뒤 바꾸지 않고 그대로 적용했다. 두 방식 모두 정합성 검증을 통과해 1순위에서 동점이었고, 2순위 deadlock 에서 갈렸다 (99건·39건 vs 0건·0건).

비관적 락은 excludeOrderId 조건을 제거해 실행계획을 개선한 뒤에도 deadlock 이 99 → 97 로 거의 변하지 않았다. lock graph 채집 결과 원인은 인덱스 선택이 아니라 INSERT 한 테이블을 같은 트랜잭션에서 FOR UPDATE 로 스캔하는 구조 자체였다.
p95 지연은 판정에서 제외했다. N=100 에서 비관적 락의 성공 표본은 1건, Conditional UPDATE 는 100건으로 표본 수가 100배 달라 비교가 성립하지 않기 때문이다.
